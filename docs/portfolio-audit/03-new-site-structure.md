# 03 — الهيكل المقترح للموقع

## 1. المبدأ

موقع واحد بثلاث طبقات تشترك في **هوية واحدة** و**مصدر محتوى واحد**:

```
                    ┌─────────────────────────────┐
                    │  الهوية: GAOBA Editorial     │
                    │  (ألوان + خطوط + مكونات)     │
                    └──────────────┬──────────────┘
          ┌────────────────────────┼────────────────────────┐
   الطبقة المهنية             طبقة GAOBA AI               طبقة المنتجات (لاحقًا)
   / · /work · /services       /links · /resources        /shop · /products/[slug]
   /about · /contact           /resources/[slug]          /account · /api/checkout
   (إنجليزي أولًا + عربي)      (عربي RTL أولًا)           (يعيد استخدام نموذج المورد)
```

**قرار لغوي مقترح:** الموارد وصفحة Instagram **بالعربية أولًا (RTL)** لأن جمهورها عربي. الطبقة المهنية **بالإنجليزية أولًا** لأن مسؤولي التوظيف والعملاء الدوليين يقرؤونها، مع نسخة عربية للصفحات الأساسية في مرحلة لاحقة. هذا يتجنب ترجمة كل شيء من اليوم الأول.

### نظام واحد، وظيفتان (قرارك 6)

| | **Portfolio** `(site)` | **Resources** `(gaoba)` |
|---|---|---|
| **الوظيفة** | الخبرات، المشاريع، العملاء | المحتوى، الموارد، المنتجات الرقمية لاحقًا |
| **الزائر** | مسؤول توظيف، عميل محتمل | متابع Instagram، مشتري مستقبلي |
| **اللغة والاتجاه** | EN أولًا، LTR | AR أولًا، RTL |
| **الترويسة** | اسمك الكامل + Work / Services / Resources / About + Contact | صورتك الدائرية + `@a_gaoba.ai` (مطابقة لترويسة الفيديو الثابتة) + رابط «أعمالي» |
| **الـ CTA الأساسي** | Hire / Start a project / Download CV | نسخ / تنزيل / فتح المورد |
| **كثافة الهوية** | هادئة: عاجي + حبر، الأحمر نادر، بلا بلوكات حبر إلا شريط GAOBA AI | أقرب للفيديو: بلوك الحبر للبرومبتات، الأحمر للزر الأساسي والشارات |
| **الحركة** | ظهور بسيط مرة واحدة | لا حركة تقريبًا (السرعة أولًا على الهاتف) |
| **النبرة** | مهنية ومختصرة، بالفصحى أو الإنجليزية | قريبة من نبرة الفيديو، ومراجعة منك |

**المشترك (لا يتكرر):** الـ tokens، والخطوط، والأزرار، والبطاقات، والـ Footer، و`SITE_URL`، و`profile.ts`. **المختلف:** layout كل مجموعة، والترويسة، ومكونات `components/resources/*`.

**الجسور بين الجزأين:** شريط «GAOBA AI» في رئيسية Portfolio (أحدث 3 موارد)، وزر «أعمالي / اطلب خدمة» في `/links` وفي أسفل صفحات الموارد. لا يُعرض محتوى الموارد في Portfolio، ولا تُعرض الخبرات في Resources.

### بنية المجلدات المقترحة (تعتمد على المشروع الحالي)

```
app/
  (site)/                     ← Route group للطبقة المهنية (layout: lang="en")
    layout.tsx
    page.tsx                  ← الرئيسية
    work/page.tsx
    work/[slug]/page.tsx
    services/page.tsx
    about/page.tsx
    contact/page.tsx
  (gaoba)/                    ← Route group لطبقة GAOBA AI (layout: lang="ar" dir="rtl")
    layout.tsx
    links/page.tsx
    resources/page.tsx
    resources/[slug]/page.tsx
    resources/[slug]/opengraph-image.tsx
  sitemap.ts  robots.ts  manifest.ts
components/
  brand/      ← Logo, Header, Footer, PaperGrid
  ui/         ← button, dialog, input, label, textarea (المستخدم فقط)
  resources/  ← ResourceCard, CopyButton, DownloadButton, ShareButton, ReelEmbed, Filters
content/
  profile.ts              ← الاسم، الروابط، البريد، سنوات الخبرة (مصدر واحد للحقيقة)
  projects/*.mdx
  resources/*.mdx
lib/
  content.ts              ← قراءة + تحقق (zod) + فرز
  site.ts                 ← SITE_URL، الثوابت
public/
  downloads/<slug>/...    ← ملفات الموارد المجانية
  brand/                  ← الصورة الرسمية (نفس creator.png المستخدمة في الفيديوهات)
```

> **لماذا Route Groups بـ layout جذري لكل مجموعة؟** في Next.js App Router يمكن أن يكون لكل route group ملف `layout.tsx` جذري خاص به يحتوي `<html lang dir>`. هذا يعطي `lang="ar" dir="rtl"` صحيحًا لصفحات الموارد من الخادم دون JavaScript ودون مكتبة i18n. **المقابل:** الانتقال بين المجموعتين يعيد تحميل الصفحة كاملة، وهذا مقبول لأن الزائر نادرًا ما يتنقل بين الطبقتين.

## 4. مسارات الزوار (User Journeys)

| الزائر | يصل من | ما يريده في أول 10 ثوانٍ | المسار المقترح | CTA الأساسي | CTA الثانوي |
|---|---|---|---|---|---|
| **مسؤول توظيف** | LinkedIn / CV / Google | من أنت، ماذا تتقن، هل خبرتك حقيقية | `/` ← بطاقة «Hiring?» ← `/about` (خبرة، تعليم، مهارات) ← `/work/[slug]` | **Download CV** | Email / LinkedIn |
| **متابع Instagram** | رابط Bio أو DM | البرومبت/الملف الذي في الفيديو | `/links` ← «أحدث مورد» ← `/resources/[slug]` ← **نسخ** | **نسخ البرومبت / تنزيل** | «موارد مشابهة» ثم «تابع @a_gaoba.ai» |
| **عميل محتمل** | توصية / Google / Instagram | هل يقدر ينفذ مشروعي؟ أمثلة؟ كيف أتواصل؟ | `/` ← «Need a project?» ← `/services` ← دراسة حالة ← `/contact` | **Start a project** (نموذج) | حجز مكالمة 15 دقيقة |
| **مشتري مستقبلي** | موارد مجانية متكررة | قيمة أكبر من المجاني | `/resources/[slug]` (مجاني) ← بطاقة «النسخة الكاملة» ← `/products/[slug]` ← الدفع | **احصل على الحزمة** | الاشتراك في البريد (موارد جديدة) |

**قواعد الـ CTA:**
- زر أساسي واحد لكل شاشة.
- الأحمر للزر الأساسي فقط، والباقي حبر أو إطار.
- لا نوافذ منبثقة، ولا عدادات تنازلية، ولا «عرض لفترة محدودة».
- المجاني يبقى مجانيًا فعلًا: **لا بريد إلكتروني إلزامي للحصول على مورد مجاني**. المتابع وُعد في الفيديو بأن المورد في البايو، وطلب بريده الآن يكسر الثقة. الاشتراك يكون اختياريًا أسفل الصفحة.

## 5. النطاق (Domain) — قرارك 8

- **المعتمد الآن:** `https://gaoba.vercel.app`.
- **إعداد مركزي واحد:** `lib/site.ts` ← `SITE_URL = process.env.NEXT_PUBLIC_SITE_URL ?? "https://gaoba.vercel.app"`. كل من metadata وcanonical وsitemap وrobots وJSON-LD وصور OG وسكربتات الموارد (`verify-resource.mjs`) يقرأ منه.
- **عند شراء نطاق لاحقًا:**
  1. ربطه في Vercel.
  2. تغيير `NEXT_PUBLIC_SITE_URL` في إعدادات Vercel (بلا تعديل كود).
  3. إعادة توجيه 301 دائمة من `gaoba.vercel.app/*` إلى النطاق الجديد، **فتبقى كل الروابط المرسلة سابقًا في DMs والتعليقات تعمل.**
  4. إعادة `verify-resource.mjs` لكل مورد منشور.
- يُحذف `abdulrahmangooba.dev` من الكود نهائيًا (لا يعمل).
